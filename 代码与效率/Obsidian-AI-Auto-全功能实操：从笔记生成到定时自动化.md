## 从社区市场安装，找到插件入口

1. 在 Obsidian 打开 设置 → 第三方插件 → 浏览。视频里的市场安装放在「找到插件与模型设置」（00:12）章节。
1. 搜索 yuhanbo-ai-auto，进入详情核对 3.1.2 和作者，再点击 安装、启用。
1. 打开一篇 Markdown 笔记，按 Ctrl+P 搜索插件名，确认看到「直接调用AI生成内容」。配置入口是 设置 → yuhanbo-ai-auto，也可从插件市场详情点击 选项。小节标题中的时间可在配套实操视频里直接定位。

## 先把模型和入口配清楚

| 设置 | 怎么用 |
| --- | --- |
| 默认文本模型 | 决定生成窗初始选中的模型。也可以在单次生成前从下拉框切换。 |
| Codex / OpenCode CLI | 先按本机各自的方式安装并登录；需要时指定 CLI 路径、具体模型和超时。默认文本配置为 Codex CLI，默认模型为 GPT-6-luna。 |
| OpenRouter、Gemini、DeepSeek、SiliconFlow | 根据使用的服务填写对应密钥，密钥配置在当前库。不同服务支持的模型和输入方式不同。 |
| OpenAI 兼容供应商与自定义模型 | 先添加供应商的接口和凭据，再把自定义模型绑定到供应商。选择模型时核对具体模型 ID。 |
| 商品模板使用的模型 | 供对应模板动作独立选模型，普通笔记生成使用生成窗当前选中的模型。 |## 文本写回的三种方式（00:47）

### 直接生成并写回

1. 打开原稿，点击待办标题下方的编辑位置。按 Ctrl+P，搜索并选中带插件名的 直接调用AI生成内容。
1. 在输入提示词窗口核对模型。填入原稿，再写清要求，例如“整理为 Markdown 待办，保留负责人、日期和待确认项”。
1. 点击右下角 提交 或按 Enter。看到生成提示后，留在原笔记并核对新清单以及上方保留的原稿。
### 选区插入和替换（01:21）

* 调用AI生成并插入内容。先选中一段原文，再输入补充或改写要求。结果插在选区之后，原文可以继续核对。
* 调用AI生成并替换内容。先选中确实需要改写的句子，再输入要求。结果替换选区，选区之外的标题、分隔线与段落应保留。
实录中直接生成得到“星期二小林核对流程清单”“星期四小周准备演示素材”和一条待确认的发布日期。插入示范在原提醒后增加版本号与核对日期，替换示范把“材料尽快给我一下”改为带截止时间的请求，并保留分隔线之后的说明。替换前确认文本选区，生成后用编辑器撤销或历史版本处理需要回退的结果。

## 用模板和快速命令减少重复操作（01:51）

在库中建一个提示词目录，把每个模板写成 Markdown。给「提示词模板路径」填库内目录路径。多个目录可用逗号、分号或换行分隔。

在生成窗敲半角 /，选择「周会待办」。模板正文会替换斜杠，仍可以追加本次要求。需要固定入口时，用「快速生成配置」记录名称、模型、模板和上下文长度，再在命令面板搜索配置名，如「本周待办」。把光标放到素材之后，插件才会把光标前指定长度的内容和模板一起提交。预览出来后，按 Tab 确认写回，按其他键取消。快捷键可在 Obsidian 中绑定。

例如把这句存为模板：“把本次提供的周会记录整理成三条 Markdown 待办。保留负责人、截止时间和待确认事项。只输出清单。” 把新周会记录留在正文，下次只需把光标放到记录之后运行预设。

## 检索已有知识库并核对来源（02:28）

1. 在 知识库管理 选择资料目录、向量目录、嵌入服务和模型。资料用 Markdown。向量存放在单独目录，避免与原文混放。
1. 创建后确认索引已经完成。平时用「增量更新」处理新增或修改的文件。更换嵌入模型后，用「强制更新」重建旧索引。
1. 打开生成窗，敲半角 @，选择知识库。选中状态显示在提示词上方。输入只在资料中有答案的问题，再确认写回结果。
1. 用在线嵌入时，资料正文会发给所选服务。使用 Ollama 时，确认填写的地址对应自己管理的服务，并加载适合的嵌入模型。
录制时，用 SiliconFlow 的 BAAI/bge-m3 对测试资料建索引。问“蓝色信封怎么交接”，实际写回“星期四，西侧门岗，ORCHID-4837-AURORA”。问题与当前笔记里都没有识别码，可以与索引目录对应的原文逐项核对。

## 图片、语音和视频

### 图片生成（03:05）

1. 在笔记正文确定光标位置，运行「直接生成图片」，写清主体和画面要求，然后选图片模型。
1. 设置页的「图片生成设置」管理保存路径、模型、尺寸、宽高比及数量。
1. 实录用 Kolors 生成一张 1024 × 1024 的周报配图，笔记写入图片引用，库内保存目录同时出现 PNG。视频中点击左侧文件树的「图片」文件夹，打开实际写出的文件进行对照。
### 语音合成（03:33）

市场版 3.1.2 的 SiliconFlow 语音选项指向 SenseVoiceSmall，它用于识别语音。该版本的 Gemini 语音入口亦未实现合成。尝试替换为 SiliconFlow CosyVoice2 时服务返回 HTTP 402。最终实录在测试库临时适配版接入小米 MiMo，使用 mimo-v2.5-tts 和茉莉音色。

1. 在插件设置找到「语音和视频设置」，核对默认语音模型及媒体目录。该适配版从本机密码管理器读取事先配置的 MiMo 凭据。
1. 进入要写回的笔记，运行「直接调用AI生成内容」，下拉选择「小米 MiMo TTS」。
1. 输入一段测试播报，提交。回到笔记，点嵌入播放器试听。文件名以 generated_speech_ 开头，格式为 MP3。实录文件实测约 7.1 秒，已在笔记内播放。可以单独打开这个录屏示例的原声。测试库语音生成试听
### 视频生成（04:07）

市场版 3.1.2 使用的 Wan2.2 接口已经无法继续生成。本段临时适配版改用 SiliconFlow 的 MiniMax H3，依次提交、查询任务状态、下载文件、写回笔记。

1. 在「语音和视频设置」核对默认视频模型，进入生成窗选「SiliconFlow MiniMax H3」。
1. 写明主体和动作。演示提示词描述桌面、紫色活页夹、复选框和镜头推进。
1. 提交后查看运行提示，等待文件写回，再在 Obsidian 的播放器中播放。演示请求为 5 秒、480p、16:9，结果保存在「媒体」目录，实际文件为 864 × 480，约 5.17 秒。
[小米 MiMo 语音合成文档](https://mimo.mi.com/docs/en-US/api/audio/tts-post) · [SiliconFlow 语音合成文档](https://docs.siliconflow.cn/docs/api/audio-speech-post) · [SiliconFlow 视频生成文档](https://docs.siliconflow.cn/docs/userguide/capabilities/video) · [Wan2.2 下线公告](https://docs.siliconflow.cn/docs/release-notes/overview?release=api-service-adjustment-userinfo-endpoint-deprecation)

## 定时任务和后台索引（04:39）

* 定时任务。配置源 Markdown、目标目录、模型、执行类型和时间。源文件可直接写任务提示和素材。单次执行适合验收，每日执行适合固定简报。到点保持 Obsidian 打开。单次成功任务会移除；展开定时任务所设的「输出」目录，点击「定时周会简报」，核对新文件及正文。
* 知识库自动更新。开启全局自动更新和单个知识库的自动更新。演示在资料中补入“接收人代称为银杏，复核时间为下午三点”，自动索引后复问，得到“银杏，下午三点”。
* 定时任务、自动索引与邮件通知需要有效的自动化授权。视频复用测试库此前的任务执行和收件记录，本次补拍打开已生成的文件。手动生成、手动更新与手动检索可以单独使用。
## SMTP 邮件通知（05:17）

1. 在插件设置打开「启用邮件通知」，填写 SMTP 主机、端口、发件账户、服务凭据、发件人名称和收件地址。该插件从连接开始使用 TLS，应选择邮箱服务支持的隐式 TLS 端口。
1. 点击「发送测试邮件」，看客户端状态，并在收件端核对主题和正文。
1. 定时通知还需在任务中保留「发送邮件通知」，到点后核对输出 Markdown 以及第二封任务邮件。
1. 本次用 127.0.0.1:24665 的测试 SMTP 收件箱，虚构地址仅作演示，实测连接协商 TLS 1.3，认证返回 235，测试邮件和定时任务邮件均返回 250 Accepted。这里的本地证书只被临时测试构建信任。
## 本地 HTTP 接口（05:50）

1. 在「本地 HTTP 接口」设置并保存至少 32 位随机令牌。市场版默认绑定 127.0.0.1:27123，本次为避免占用现有端口，测试构建使用 127.0.0.1:27125。
1. 客户端发 POST /，设置 Content-Type: application/json 并携带 Authorization: Bearer <令牌>。不带令牌会返回 401。令牌仅保留在本机受信任的客户端。
1. 用 getTemplates 列出库内目录的模板，再以 getTemplateContent 读取指定 Markdown。用 saveContent 向指定的库内目录写出 Markdown，本次认证请求都返回 200，并在 Obsidian 打开输出 Markdown 核对了正文。
| 操作 | 请求中的关键字段 |
| --- | --- |
| 列表 | {"action":"getTemplates","path":"演示目录","searchText":"HTTP模板"} |
| 读取 | {"action":"getTemplateContent","path":"演示目录/HTTP模板.md"} |
| 写回 | {"action":"saveContent","path":"演示目录/输出","content":"# HTTP 写回验收"} |![](https://xz.sanrenjz.com/image/%E5%AE%9E%E5%BD%95%E6%88%AA%E5%9B%BE-%E5%9B%9B%E9%A1%B9%E8%A1%A5%E5%BD%95.png?imageSlim)

## 辅助入口与数据范围

本地 HTTP 接口默认关闭。配置令牌后监听 127.0.0.1:27123，供受信任的本机客户端使用。请求使用 Authorization: Bearer <本地令牌>，提供模板列表、Markdown 模板读取和生成结果写入。调用老接口的客户端需要适配认证请求头。

Windows 可以从库内文件夹右键复制路径或打开 PowerShell，iflow 入口需要本机已有可执行文件。使用在线生成时，提示词以及选中用于当前操作的文本、图片、模板或检索片段会发送给所选提供商。API 密钥、邮箱凭据和授权信息位于插件的本地配置，录屏和分享时应避开这些字段。
